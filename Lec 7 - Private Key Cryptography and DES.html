Secret Key Cryptography and DES

How a shared key turns readable data into nonsense and back again, how the Data Encryption Standard actually does it round by round, how block ciphers scale up to whole messages, and why one round of DES eventually needed to become three.

1. Secret key cryptography 2. DES 3. Multiple encryption DES Takeaways

Where this fits. Last lecture's mechanisms, encryption, hashing, signatures, all rest on cryptography actually working. This lecture opens that box for the symmetric side: one shared secret, used to scramble data and to unscramble it again. DES is the historical anchor for this whole family of algorithms, and understanding its internals makes every modern block cipher, including AES, far easier to read.

4 ideas build on each other here: what a secret key even buys you, how DES turns a key and a block of data into ciphertext through 16 repeated rounds, how you stretch a cipher that only handles 64 bits at a time across a message of any length, and how three rounds of DES were stitched together to outlive DES's key size problem.

01

Secret key cryptography

One key, shared in advance, does both jobs: locking the message and unlocking it again.

Definition

Secret key cryptography, also called symmetric key cryptography, uses the exact same key to encrypt a message and to decrypt it. Whoever holds the key can do either operation, which means both the sender and the receiver need a copy of it before any secret communication can happen.

Watch the diagram below. Alice encrypts her plaintext P into ciphertext C using key K. That ciphertext travels over a channel anyone might be listening on. Without the key, the eavesdropper sees only noise. Bob, holding the same key K, reverses the operation and recovers P exactly.

The packet crossing the channel is ciphertext. Eve can capture it freely, she just cannot read it without K.

Why this is harder than it sounds

The entire scheme depends on one requirement that has nothing to do with mathematics: Alice and Bob need to agree on K before they can talk securely, and they need to do that agreeing over some channel that is itself trustworthy. This is called the key distribution problem, and it is the single biggest practical weakness of symmetric cryptography. Public key cryptography, covered separately, exists largely to solve exactly this problem.

Kerckhoffs's principle

A cipher should stay secure even if everything about the algorithm is public knowledge. Only the key needs to remain secret. DES, AES, and essentially every serious modern cipher are published in full detail and still considered secure, because their security lives in the key, not in obscurity.

Block ciphers

Operate on fixed size chunks of data at a time, 64 bits for DES, one hundred twenty 8 bits for AES. A block goes in, a block of the same size comes out.

Stream ciphers

Encrypt data one bit or byte at a time by combining it with a continuously generated keystream, usually through XOR. Useful when data arrives as a stream rather than in fixed chunks.

DES and its descendants are block ciphers, and the rest of this lecture is built around that fact. A block cipher gives you a strong way to scramble 64 bits. Making that useful for a ten megabyte file is a separate problem, which is exactly what section three works through.

02

Data Encryption Standard (DES)

A 64 bit block cipher built from 16 identical rounds of substitution and permutation.

DES was developed by IBM in the early 1970s, refined from an earlier cipher called Lucifer, and adopted as a United States federal standard in 1977. For roughly two decades it was the default encryption algorithm across banking, government, and commercial systems. It is no longer considered secure on its own, its key is simply too short for modern hardware, but its internal design, the Feistel structure, is the direct ancestor of how block ciphers are still explained and analyzed today.

64

Block size

Every encryption operation processes exactly 64 bits of plaintext into 64 bits of ciphertext.

56

Effective key size

The key is stored as 64 bits, but 8 of those are parity check bits, leaving 56 bits of real key material.

16

Rounds

The same round function is applied 16 times in sequence, each time with a different 48-bit subkey.

48

Subkey size

Each round consumes its own 48-bit round key, derived from the original 56-bit key through the key schedule.

The Feistel structure

DES belongs to a family of ciphers called Feistel networks, named after Horst Feistel, who led the Lucifer project at IBM. The trick behind a Feistel network is that it turns any function F, even one that cannot be undone on its own, into an operation that can always be reversed. That matters because decryption has to be possible, and it means F itself can be as complicated and irregular as you like.

Here is the mechanism. The 64-bit block is split into two 32-bit halves, called L (left) and R (right). In each round:

The old right half, untouched, becomes the new left half. L and R have effectively swapped roles.

Inside the round function F

F is where DES's actual mixing happens. It takes the 32-bit right half and the round's 48-bit subkey and produces a new 32-bit value through 4 steps:

1. Expansion

E: 32 → 48 bits

Duplicates some bits so the 32-bit half can be XORed with a 48-bit subkey. Some input bits influence two output positions.

→
2. Key mix

XOR with Ki

The expanded 48 bits are XORed with this round's 48-bit subkey, injecting the secret key into the data.

→
3. Substitution

8 S-boxes: 48 → 32 bits

The 48 bits are split into 8 6-bit chunks, each passed through its own substitution table, producing 8 4-bit outputs.

→
4. Permutation

P: 32 → 32 bits

The 32 bits from the S-boxes are reordered according to a fixed table, spreading each S-box's influence across the whole block.

The S-boxes carry almost all of DES's real security. They are the only nonlinear part of the algorithm, the only part that cannot be described as simple bit shuffling, and their exact values were chosen deliberately (and, for years, controversially, since the design criteria were not published until decades later) to resist certain attacks.

Key schedule: deriving 16 subkeys from one key

DES never uses the 56-bit key directly. Instead, it runs a key schedule once at the start to produce 16 different 48-bit subkeys, one per round. The process: the 64-bit key is first reduced to 56 bits by dropping the 8 parity bits (via a table called PC-1), then split into two 28-bit halves, C and D. Before each round, both halves are rotated left by one or two bit positions (the exact amount is fixed per round), and a second table, PC-2, picks 48 of the resulting 56 bits to form that round's subkey.

Each half rotates left before every round. PC-2 then samples 48 bits from the rotated C and D to build that round's subkey Ki.

Because C and D rotate a little further each round and PC-2 samples a different combination of positions every time, all 16 subkeys end up different from each other, even though every one of them is derived from the exact same original key.

Initial and final permutation

Wrapped around the 16 Feistel rounds are two more steps: an Initial Permutation (IP) applied to the plaintext before round one, and its exact inverse (IP-1) applied after round 16. These two steps just reorder bits according to a fixed table. They contribute no cryptographic strength on their own, historically they were included to make the algorithm easier to wire into 1970s hardware, but they do have to be applied for standard DES output to match, so any implementation needs to include them.

DES defines 8 such tables, S1 through S8, one per 6-bit chunk of the expanded half. Each was hand-picked to satisfy strict design criteria around avalanche and resistance to differential analysis.

Decryption: the same machine, run backward

This is the payoff of the Feistel structure. Decrypting with DES uses the identical sequence of steps, the same F function, the same S-boxes, the same everything, except the 16 subkeys are applied in reverse order: K16 first, K1 last. No separate decryption algorithm has to be designed or implemented. That symmetry is a large part of why Feistel networks became the dominant block cipher design for decades.

Why DES eventually failed

DES's structure has held up remarkably well against decades of cryptanalysis; no practical shortcut attack meaningfully beats brute force. Its weakness is simply arithmetic: 56 bits means 256, about 72 quadrillion, possible keys. In 1977 that was computationally out of reach. By 1998 the Electronic Frontier Foundation built a purpose-made machine, nicknamed Deep Crack, that found a DES key by brute force in under three days. Today a determined attacker with modern hardware can do it faster still. The algorithm's internal design was never the problem. The key was simply too short for the hardware that eventually caught up to it, which is precisely the motivation for section four.

03

Multiple Encryption DES (EDE)

Running DES three times, encrypt, decrypt, encrypt, to outrun a 56-bit key without redesigning the cipher.

Once the 56-bit key became a real liability, the industry needed a fix that did not require replacing every DES chip and piece of software already deployed. The answer was to keep DES exactly as it was and simply apply it more than once, using multiple independent keys.

Why not just encrypt twice?

The obvious first idea, double DES with two keys K1 and K2, computing C = EK2(EK1(P)), looks like it should square the effort needed to break it, roughly 2112 instead of 256. It does not. A technique called the meet in the middle attack defeats double DES using only roughly double the work of breaking single DES, not the square of it. The attacker encrypts the known plaintext forward under every possible K1 and separately decrypts the known ciphertext backward under every possible K2, storing both lists and looking for a match in the middle. That collapses the effective security of double DES to only a little more than single DES, which made it not worth the extra computation.

The EDE construction

Triple DES, formally called Triple DES EDE (Encrypt, Decrypt, Encrypt), sidesteps the meet in the middle weakness by using three keys and three operations in this specific order:

Why the middle step is a decryption, not another encryption

The middle decrypt step is a deliberate compatibility trick, not a security requirement. Set K1, K2, and K3 all equal to the same key, and the decrypt in the middle cancels the encrypt right before it, leaving the whole construction behaving exactly like a single, ordinary DES encryption with that one key. This lets 3DES-capable hardware and software stay fully backward compatible with systems that only ever spoke plain single DES, simply by feeding it three identical keys.

3-key 3DES

K1, K2, K3 all different

168 bits of raw key material. Because of meet in the middle style attacks the effective security is closer to 112 bits, still far beyond brute force with current technology.

2-key 3DES

K1 = K3, K2 different

112 bits of raw key material, a common cost saving variant. Effective security is somewhat lower still, and this variant is now discouraged in new designs.

1-key (K1=K2=K3)

Backward compatible mode

Behaves identically to single DES. Exists purely so 3DES hardware can talk to legacy single DES systems.

The cost of the fix

3DES buys back security by paying with speed: it runs DES three full times per block, so it is roughly three times slower than single DES and noticeably slower than AES, which was designed from scratch afterward specifically to replace both. 3DES is still found in legacy systems today, older payment card terminals and some banking infrastructure in particular, because of how deeply it was embedded before AES arrived in 2001. It has been formally deprecated by NIST for new use since 2023. For any new design, AES is the correct default, but understanding 3DES's EDE construction is what makes clear why simply chaining a weak cipher twice does not automatically double its strength, a lesson that generalizes well beyond DES.

05

Key takeaways

Before the next lecture
  1. Secret key cryptography uses one shared key for both encryption and decryption, which makes key distribution the central practical challenge.
  2. DES encrypts 64-bit blocks through 16 Feistel rounds, each mixing in a different 48-bit subkey derived by the key schedule from a single 56-bit key.
  3. The Feistel structure makes decryption free: run the identical algorithm with subkeys in reverse order.
  4. Triple DES (EDE) chains encrypt, decrypt, encrypt with up to three keys to defeat the meet in the middle attack that breaks naive double DES, buying more effective key strength at roughly three times the computation.

01

What is a security mechanism?

A rule such as "only staff may enter the server room" does not protect anything by itself. A mechanism is the actual thing that enforces the rule: a locked door, a checkpoint, a scrambled file.

Security requirementPossible mechanism
Prevent unauthorized physical entryGate, lock, security guard
Prevent unauthorized network accessFirewall
Verify identityAuthentication
Restrict what a user can doAuthorization
Protect information in transit or at restEncryption
Detect modificationHashing / MAC
Prove who created a messageDigital signature
Hide the existence of a messageSteganography

Four mechanisms make up this lecture: gates and guards control people and traffic at a boundary; cryptography and steganography control the information itself. The first two are not purely physical; each one has both a physical and a logical (digital) form.

03

Gates

A gate is a barrier that decides whether someone, or some data, can pass from a less-trusted area into a more-trusted one.

Public / untrusted area
↓
GATE
↓
Protected / trusted area

A gate is not only physical. Any boundary that people or traffic must pass through counts, including a firewall.

Physical gate

  • Turnstiles, barrier arms, security fences
  • Locked doors, data-centre access doors
  • A mantrap: two doors, only one opens at a time, so nobody sneaks in behind you

Logical gate

  • Firewall: examines every packet
  • Authentication gateway: valid credential in, invalid denied
  • API gateway: checks every request before it reaches a service

Guards

A guard watches, thinks, and decides. Unlike a gate, it can use judgement, noticing something feels wrong even when no rule says so.

Physical guard

  • A real person: checks IDs, watches CCTV
  • Uses common sense on unusual situations

Logical guard

  • IDS / IPS: watches network traffic
  • SIEM: collects alerts across systems
  • SOC analyst: a person watching the software

05

Preventive, detective & corrective controls

Every security control is generally trying to do one of three things, and together they form a cycle that never really stops.

Preventive

Stops trouble before it starts. Firewall, password, locked door, encryption.

Detective

Notices trouble as it happens. IDS, CCTV, audit logs.

Corrective

Fixes things afterward. Restoring a backup, resetting a password.

A mature setup uses all three together. One type alone is never enough.

Cryptography

Cryptography turns a readable message (plaintext) into scrambled nonsense (ciphertext) using a key, so only someone with the matching key can turn it back.

Plaintext
MEET AT 10
→
Encrypt (key K)
→
Ciphertext
X7$K9@P2
→
Decrypt (key K)
→
Plaintext
C = E(K, P): encrypt plaintext with key K to get ciphertext
P = D(K, C): decrypt back with the same or matching key

The method can be public; only the key needs to stay secret. This is Kerckhoffs's principle: a system should stay secure even if everyone knows exactly how it works, as long as they don't have the key.

Symmetric vs. asymmetric

Symmetric: one shared key

  • Same key locks and unlocks
  • Fast, good for large files
  • Hard part: sharing the same secret key safely
  • Examples: AES, ChaCha20

Asymmetric: two different keys

  • Public key locks, private key unlocks
  • Slower, but the public key can be shared freely
  • Also used for digital signatures
  • Examples: RSA, ECC

Steganography

Hides a message so well that nobody knows it exists. Cryptography hides meaning. Steganography hides existence.

Secret message + cover image
→
Steganography algorithm
→
Stego object, looks ordinary
Pixel value: 10110110, last bit changed to 10110111
The shift is too small to see, but it can carry hidden data across thousands of pixels.
Combining the two: encrypt, then hide
Secret message
↓

↓

↓
Two layers: hidden AND unreadable
Best practice: if someone finds the hiding spot, they should still only get unreadable ciphertext, not the real message.

Steganalysis is the flip side: hunting for tiny statistical patterns that reveal hidden data. A watermark is different again: it embeds ownership information meant to survive resizing, not stay secret.

09

Principles worth memorising

1 · Defense in depth

Stack layers so one failure isn't the whole story.

2 · Least privilege

Give people only what they need, nothing more.

3 · Fail securely

When something breaks, default to locked, not open.

4 · Complete mediation

Check every request. Never assume a past approval still holds.

5 · Separation of duties

Split sensitive tasks between two people.

Common misconceptions

"Encryption makes a system completely secure."
No. It doesn't stop malware, social engineering, weak passwords, or insider threats.
"Steganography is encryption."
No. Encryption hides meaning, steganography hides existence.
"A firewall is enough."
No. It's one layer among many needed.
"If a user is inside the network, they can be trusted."
Zero Trust rejects this. Being inside no longer means automatic trust.
10

Recap

Every mechanism answers the same question, for a different situation: how do we stop someone who isn't allowed in? Gates and guards do it for people and networks. Cryptography and steganography do it for information.

Gate
A barrier, physical or logical, that only lets through what's allowed.
Guard
A person or program that observes, decides, and responds.
Mantrap
Two doors in sequence; the second won't open until the first is shut.
Cryptography
Scrambling a message with a key.
Steganography
Hiding that a message exists at all.
Defense in depth
Stacking controls so one failure doesn't expose everything.
Zero Trust
Never trust automatically, verify every time.

Classroom activity

Scenario: design a security setup for a university exam database using at least 2 gates, 2 guards, 2 cryptographic mechanisms, and 1 information-hiding mechanism. Then ask: if the firewall fails, what protects the database next?

Quick check

Is a firewall a gate or a guard?
Both. It decides what's allowed (guard-like) and blocks the rest (gate-like).
Why hide a message after encrypting it, rather than just hiding it?
If the hiding spot is found, the attacker still only gets scrambled, unreadable text.
